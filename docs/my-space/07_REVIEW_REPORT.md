## 2차: 코드 구조와 연결 검사

공통 정책/기준표/검토 저장소 분리를 확인했다. match.js에 일부 역할별 폼이 남아 있으므로 완전한 구조 정리가 끝났다고 표현하지 않는다. 실제 인증 상태를 반환할 수 있어도 참가자 기능은 계속 잠겨 있다.

수집기/importer 필드 불일치를 normalize-snapshot.mjs로 해결했다. 성공·완전성·건수·중복·공식URL·모집bool/null을 검증한다. 원본 결과는 보존한다. 메모리 SQLite에서 32개 반영·17개 공식 모집·재반영 ID 보존·모집글/상태 보존을 검사했다. 실패/부분/빈/중복/비공식 source 입력 거부를 검사했다. 운영 DB 쓰기는 수행하지 않았다.

최신 소스의 npm test가 오래된 ‘7일 확인 원칙’ 정적 문구 검사에서 실패했다. 인계본에서 그 검사만 확정된 ‘마지막 메시지 후5일 미응답 종료’로 갱신한 뒤 통과했다. 최신 공통 정책의 경계/답변 시 기한 재계산/종료 대화 부활 금지 행동 테스트는 유지했다. 운영 UI를 새 규칙으로 임의 수정한 것이 아니다.

## 3차: 경로·설정·Git 전달 검사

`/my-space/` 자산 경로, 동적 auth-config rewrite, 현재 `/auth/*` callback·`/verify-email`·`/admin` 경로 계약, same-origin 쿠키/CSRF, Node/SQLite 호스팅 제약을 대조했다. 실제 공식 repo의 routing/배포 설정은 아직 조회하지 않아 적용 완료로 표시하지 않았다.

지예만 키를 관리하려면 Secret 저장 외에 production 배포/DB 접근권한을 제한해야 함을 명시했다. 실제 env·개인자료·DB·node_modules·Git 인증정보를 제외한 산출물만 묶었다. 파일별 SHA-256와 ZIP 내부 파일 일치 검증 결과는 MANIFEST.json으로 확인할 수 있다.
