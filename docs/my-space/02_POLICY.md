# 최신 통합 정책

## 인증·등록·승인

Google/Naver 로그인 계정과 NASA 등록 이메일을 별도로 관리한다. 내부 participant_id는 불변이다. 직접 입력한 NASA 이메일만으로 연결하지 않는다. 제공자가 검증한 이메일이 해당 행사의 이미 승인된 적격 참가 기록 한 명과 유일하게 일치하면 자동 연결할 수 있다. Naver 이메일을 검증된 것으로 추정하지 않는다.

불일치 경로는 NASA 이메일 입력→소유 인증→운영자 공식 등록·Seoul 선택·서울 Form·이름·기존 연결 대조→수동 승인이다. 이메일 인증, 참가 등록 자격, 계정 연결 승인을 각각 구분한다. 이름의 한글/영문 차이는 추가 검토 사유다. 인증 완료로 미성년 보호자 확인·팀 소속·연락 동의를 변경하지 않는다. 메일 답장 OK/mailto로 DB를 자동 승인하지 않는다.

링크는 요청 identity와 승인 요청에 묶는다. 해시 저장·만료·재발송 시 이전 링크 철회·1회 소비·명시적 POST 확인을 사용한다. 단순 GET/메일 검사기 방문은 인증 완료가 아니다. 30분 TTL·60초 간격·시간당 3회·전체 하루 100회는 현재 코드 기본값이며 **운영 정책 최종 확정값이 아니다**.

## 화면·프로필·팀

| 항목 | 기준 |
|---|---|
| 탐색 | 5테마+전체의 6버블, 팀/대원 토글 |
| 대원 목록 | 승인된 참가자에게만 실제 데이터 반환 |
| 역할 | 현재 최대 3개·희망 최대 3개, 관심 Challenge 최대 3개 |
| 메뉴 | 참가자: 프로필+받은/보낸 관심. 오너: 프로필+내 팀 관리+받은 관심+보낸 관심 |
| 찾기/모집 | seeking·paused·completed; 오너 개인 찾기·팀 모집·NASA 공식 모집은 별도 |
| 소속 | 검증된 Membership만 가입 근거. 관심/이메일은 가입 확정이 아님 |
| 팀 공식 정보 | 팀명·Challenge는 공식 출처, 허브 오너 수정 금지 |
| 모집 수정 | 역할 최대 5개·문구 최대 240자, 확인 팝업 안의 저장에서 반영 |

## 관심 대화

첫 관심 포함 시작자 3회·답변자 2회, 교대로 총 5개·각 50자. 같은 행사·같은 두 참가자 사이 최대 3개 대화·동시 활성 1개다. 팀/대원 경로·시작자 변경으로 한도를 우회하지 않는다. 팀 대상은 확인된 실제 오너 participant_id로 계산한다.

**마지막 메시지 후 120시간(5일)이 지나면 expired.** 답변 시 기한 재계산, 메시지 5개이면 completed. 종료 기록과 사용 횟수는 보존한다. 종료는 가입/거절/수신 동의 철회가 아니다. paused/completed 전환은 새 관심을 막고 기존 대화는 5일 기한 내 유지한다. 조회·생성·답변 시 서버 UTC와 트랜잭션으로 먼저 만료를 반영한다. 당사자만 대화를 조회한다.

## 이메일

관심과 이메일 동의는 별도다. 팀 카드 연락은 팀 주소가 아니라 확인된 오너에게 전달한다. 오너에게는 peerEmailOptIn(대원에게 받기), 오너→대원은 emailOptIn(Team Owner에게 받기), 대원→대원은 peerEmailOptIn을 검사한다. 별도 팀 동의를 만들지 않는다.

발송 시 수신 동의와 발송자의 자기 이메일 공개 동의를 재검사한다. 서비스의 검증 From·서버에서 확인한 Reply-To를 사용한다. 외부 답장 시 상대 주소도 공개될 수 있다. 본문·외부 답장은 저장하지 않고 발송 메타데이터만 저장한다. 오너 변경 시 기존 대화를 새 오너에게 자동 이전하지 않는다.

## 아직 결정되지 않은 항목

보관/삭제 기간, 차단 정책, 오너 검증·변경 방법, 공식/허브 모집 상태 충돌 표시, 7일 모집 재확인 적용 여부, 미성년 연락 허용, 운영자의 본문 예외 열람, 검증 연락 이메일 선택 기준, 이메일 발송 운영 상한. 미확정 규칙을 운영에서 자동 활성화하지 않는다. 약 100명×50회는 부하 가정이며 이용 한도가 아니다.
